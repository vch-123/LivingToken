# 设计模式简介

设计模式（Design Pattern）是**软件工程中一套经过验证、可复用的解决方案**，用于解决在软件设计过程中常见的问题。它们不是具体的代码，而是**编程问题的通用解决方案模板**，强调**可维护性、可扩展性、灵活性和复用性**。

---

## 🧩 一、设计模式的三大类别

| 类别           | 描述                         | 关键词                     |
| -------------- | ---------------------------- | -------------------------- |
| **创建型模式** | 处理对象创建相关的问题       | 如何创建对象、隐藏创建逻辑 |
| **结构型模式** | 关注类与对象的组合           | 如何组装类、构建更大的结构 |
| **行为型模式** | 关注对象之间的通信和职责划分 | 如何协调对象之间的交互     |

---

## 📚 二、23种经典设计模式（GoF）

### 🏗 创建型模式（5种）

| 模式                             | 作用                     |
| -------------------------------- | ------------------------ |
| **Singleton（单例）**            | 保证一个类只有一个实例   |
| **Factory Method（工厂方法）**   | 由子类决定实例化哪个类   |
| **Abstract Factory（抽象工厂）** | 创建相关或依赖对象的家族 |
| **Builder（建造者）**            | 分步骤创建复杂对象       |
| **Prototype（原型）**            | 通过克隆已有实例创建对象 |

---

### 🧱 结构型模式（7种）

| 模式                    | 作用                           |
| ----------------------- | ------------------------------ |
| **Adapter（适配器）**   | 转换接口以兼容不同类           |
| **Bridge（桥接）**      | 分离抽象与实现，使其独立变化   |
| **Composite（组合）**   | 统一对单个对象和对象组合的处理 |
| **Decorator（装饰器）** | 动态添加额外功能               |
| **Facade（外观）**      | 提供统一接口访问复杂子系统     |
| **Flyweight（享元）**   | 减少对象数量、共享数据         |
| **Proxy（代理）**       | 控制对象访问、增强功能         |

---

### 🔄 行为型模式（11种）

| 模式                                  | 作用                             |
| :------------------------------------ | -------------------------------- |
| 空对象模式                            |                                  |
| **Chain of Responsibility（责任链）** | 让多个对象处理请求               |
| **Command（命令）**                   | 将请求封装为命令对象             |
| **Interpreter（解释器）**             | 实现语言文法解释器               |
| **Iterator（迭代器）**                | 顺序访问集合元素                 |
| **Mediator（中介者）**                | 降低对象间耦合                   |
| **Memento（备忘录）**                 | 保存和恢复对象状态               |
| **Observer（观察者）**                | 一对多通知机制                   |
| **State（状态）**                     | 根据状态改变行为                 |
| **Strategy（策略）**                  | 可互换算法封装                   |
| **Template Method（模板方法）**       | 定义算法框架，延迟某些步骤到子类 |
| **Visitor（访问者）**                 | 把操作与对象结构分离             |



---

## ✅ 三、总结

| 类别   | 数量 | 包含模式                                                     |
| ------ | ---- | ------------------------------------------------------------ |
| 创建型 | 5    | Singleton, Factory Method, Abstract Factory, Builder, Prototype |
| 结构型 | 7    | Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy |
| 行为型 | 11   | Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor |

👉 **合计：23种经典设计模式**
